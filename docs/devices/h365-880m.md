### 2. AVX-512 vs AVX2 on Zen 5 Mobile (Ryzen AI 9 H365)

Ryzen AI 9 H365 (Strix Point) features a hybrid topology of 4 classic Zen 5 cores and 6 dense Zen 5c cores, utilizing 256-bit SIMD execution data paths (double-pumped 512-bit vector instructions).

Tests were run paired across default (AVX-512 enabled) and `DOTNET_EnableAVX512=0` (AVX2 fallback):

#### SimdGcdrNet (1600x1152)
- **Default (AVX-512)**: **129.0 ms**
- **AVX2 (`DOTNET_EnableAVX512=0`)**: **180.6 ms**
- **Speedup**: AVX-512 is **28.6% faster** (1.40x). GcdrNet is dominated by Winograd F(4x4, 3x3) convolutions, where `InputTransform512` and `OutputTransform512` process 16 channels in a single Vector512 pass.

#### SimdPaddleOCR (100 images, medians)

### 5. Vulkan Shader Investigation & sg32d Evaluation

1. **Vulkan Shader Performance**:
   - In GcdrNet, the pure GPU execution is 7% to 13% faster on the new engine. The e2e gap at 3200x2304 is due to thermal throttling under sustained multi-rep GPU load on the laptop's unified memory bus.
   - In PaddleOCR, the shared `conv_cm_l` family performs within 2% on `medium-vulkan-4w` and 8% on `tiny-vulkan-4w`.
2. **Evaluation of Direct-Load `sg32d`**:
   - Evaluated direct global memory loading (`sg32d`) vs the staged `conv_cm_l` shader.
   - While `sg32d` bypassed LDS staging for plain GEMM in the old standalone engine, `conv_cm_l` in `Sdcb.SimdOnnx` features a vectorized 4-column raster epilogue. Implementing an un-vectorized `sg32d` with barrier-heavy epilogue worsened small model latency (53.4 ms -> 78.5 ms).
   - Furthermore, the recently landed engine fusions (`0c449e1` - SE gate, fused attention, FPN merge) resolve the major structural overheads across both CPU and Vulkan without device-divergent shader forks.
   - Therefore, the shared `conv_cm_l` family remains the optimal and recommended Vulkan path for Radeon 880M.
